# 雏雁计划双端系统代码与技术实现方案

项目：面向老龄人群的网页无障碍体验提升技术研究与实现  
周期：2026 年 10 月至 2027 年 4 月  
负责人：苏越；成员：巩品言  
依据：《雏雁计划_每周分工与行动计划》v5.1（启动周和第 1—24 周）

## 1. 要做什么，以及本期能证明什么

我们做帮助老年人使用**不同网站**的通用网页辅助平台。用户端界面用网页技术编写，分别打包为 Mac 和 Windows 桌面软件。用户在顶部输入网址，中间的独立浏览器区域打开目标网站，右侧助手读取当前页面经筛选的标题和控件，帮助理解页面、找入口、分步操作；不确定时停下来请用户选择。开发者工作台记录网页障碍和助手卡住的位置，展示证据，支持人工修复及同条件复测。

查询、预约、填表、弹窗都是验证例子，不是产品仅有的固定功能。可重复用于不同网站的能力是打开网页、提取可见控件、查找并高亮入口、逐步核验目标、记录操作和在网页变化时停止。本期用**两个结构不同的公开网站**证明阅读与找入口等只读帮助，用**自建测试站**证明填写、本人确认和修复复测。真实网站的写入须先获授权并另行验证；不承诺兼容任意网站、验证码或第三方登录。

| 部分 | 界面入口 | 可检查的成果 |
|---|---|---|
| 用户端 | 顶部网址栏、中间网页、右侧助手、历史任务 | 导航、页面概要、找入口、高亮、步骤、暂停/恢复、资料卡、提交前核对 |
| 开发者工作台 | `/developer/tasks`、`/developer/runs/:id`、`/developer/issues/:id`、`/developer/issues/:id/retest`、`/developer/study` | 任务库、独立评测、运行证据、问题单、同条件复测和试用记录 |
| 自建测试站 | `/demo/search`、`/demo/appointment` 及弹窗场景 | 可重置的查询/表单/弹窗与有障碍版、修复版 |

结题保留四个可重放案例：两个公开网站各一次只读找入口，自建站一次带本人确认的完整表单，以及日期字段缺少标签从发现到人工修复复测。每条结论附网址、页面版本、任务、运行编号和成功或失败证据。

## 2. 代码组织与两种浏览器会话

建议使用 TypeScript 工作区：React + Vite 写两类界面；Electron 承载桌面应用；外部网站在独立 `WebContentsView` 打开，不用普通 iframe 假设能嵌入所有网站。后端提供任务、运行、问题和 AI 接口；本机可先用 SQLite，是否选 Prisma 由现有仓库和学习成本决定。下列是**待实施目录**，不是声称文件已存在。

```text
apps/
  desktop/          Electron 主进程、窗口布局、外站视图和导航
  assistant-ui/     网址栏、助手、步骤/确认/历史/帮助
  developer-ui/     任务库、记录、问题、复测和试用
  api/              任务、评测、问题、AI 与研究数据接口
  demo-site/        可重置的查询、预约、弹窗和坏/好版本
packages/
  contracts/        页面快照、动作、任务卡及运行记录类型
  page-ops/         提取、查找、重验、高亮和受控操作
  evaluator/        Playwright 隔离评测、axe、焦点和截图
  task-catalog/     已审核的场景任务卡
docs/               启动、站点、试装及能力边界说明
tests/              导航、页面变化、重复提交及四个结题案例
```

用户端操作**用户正在看的内置网页视图**；工作台评测通过 Playwright 创建**独立浏览器上下文**，用演示数据运行，不借用用户窗口、登录状态或输入值。两端共享任务字段和核验规则，不共享浏览器会话。打包前明确 API 随应用启动还是部署在受控服务器，必须验证安装包在没有开发服务器的机器上能完成既定案例。

```text
输入网址 → 主进程校验并导航中间网页 → 提取当前页摘要
         → 右侧助手展示候选 → 用户选择 → 重新核验目标 → 高亮或受控执行

开发者选择任务 → 独立评测上下文 → 步骤/焦点/截图/规则结果
               → 问题单 → 人工改测试站代码 → 同任务复测
```

## 3. 页面提取、找入口和通用动作层

第 2 周读取当前页可见标题、链接、按钮、输入框的名称与大致位置；不提取密码值、会话令牌或整页私人正文。第 3 周按用户目标从实际页面控件中提出最多三个候选，说明匹配原因；点“带我过去”只滚动并高亮，找不到就说明找不到。第 4 周制作 `find / highlight / click / fill / expect` 通用动作，在**当前视图**先检查唯一、可见、可操作，重名或缺失时暂停请用户选择。

```ts
type Candidate = {
  id: string;                 // 本次页面快照内有效
  role: "link" | "button" | "textbox" | "heading";
  name: string;
  location: string;
};
type PageSnapshot = {
  viewId: string;
  pageVersion: number;        // 变化后旧编号失效
  url: string;
  title: string;
  candidates: Candidate[];
};
type ProposedAction = {
  pageVersion: number;
  candidateId: string;
  kind: "highlight" | "click" | "fill" | "expect";
};
```

`candidateId` 是临时引用，不是长期可用的 CSS 选择器。输入新网址、返回/前进、刷新、站内跳转、单页应用路由变化和关键控件树变化后重新提取；即使未捕获动态变化，执行前仍须重验视图、网址、控件名称、可见性与唯一性。网址栏只接受 http/https；`file:`、`javascript:` 等不能交给外站视图。新窗口和弹窗有明确去向，不支持则暂停并提示。自建站可以运行已审核任务卡；陌生公开网站先由页面内容生成**只读候选步骤**，逐步让用户核对。

## 4. 外站隔离与实际兼容边界

外站视图明确设置 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。内部界面仅获得按用途划分的导航、摘要、查找、高亮和受控操作方法；主进程确认 IPC 请求来自内部界面，而非外站。不向外站暴露任意脚本执行、文件读写、系统协议打开或模型密钥。权限、新窗口、下载和非 http(s) 导航需有限制和可理解的提示；依所用 Electron 版本验证相关 API。

应用内置浏览器有自己的登录会话，不沿用 Safari、Chrome 或 Edge 的账号。若目标网站拒绝嵌入式登录、出现验证码或需要系统浏览器认证，暂停并提示用户手动处理，不声称系统浏览器的登录会自动带回。对公开网站先验证无需登录的只读流程；评测只用虚构资料和单独会话，结束或超时后释放。目标站内容不得默认发往 AI 服务。

## 5. 分步辅助、确认和历史

用户任务状态为 `待开始 → 运行中 → 等待用户选择/资料 → 等待本人确认 → 正在提交 → 已完成/失败/结果待核对`。每步交代“刚做了什么、当前网页在哪里、下一步是什么”；页面变了或目标有歧义就停下。关键提交需在助手卡上显示网站、事项与即将提交的内容，由本人确认；修改内容后原确认作废，重复点击不会发起第二次提交。

```ts
// 示例：同一条记录仅能从 WAITING_CONFIRMATION 转换一次
const changed = await db.run.updateMany({
  where: { id: runId, status: "WAITING_CONFIRMATION", confirmToken: token },
  data: { status: "SUBMITTING", confirmToken: null },
});
if (changed.count !== 1) return getCurrentRun(runId);
// 在真实执行前还要重验网页、按钮和用户核对的资料。
await submitValidatedAction(runId);
```

上述状态只阻止本应用重复发起，**不能证明网站已成功接收**。提交中断或结果不明时标为“待核对”，请用户查看网站真实反馈，不自动重试。第 14 周历史仅保存任务、网站、步骤和状态；恢复时重新核对当前页、登录和控件，不能沿用旧编号。第 15 周关闭模型接口，仍应完成已有查找和自建表单任务。

## 6. 开发者工作台和评测

任务库编辑目标、起点、步骤和完成条件；评测服务以 Playwright 独立上下文执行自建站任务，逐步记录网址、耗时、控件、焦点、结果及失败截图；在关键页面状态用 `@axe-core/playwright` 检查规则。工作台的问题单并列显示自动规则、任务是否完成和键盘/屏幕阅读器的人工结果。规则通过不等于任务成功。

第 8—11 周的首个闭环：保存日期字段缺少标签的有障碍版和失败记录，开发者依据证据**人工修改**测试站标签关联，保留同起点、同数据、同完成判据，再运行修复版；对照焦点、朗读和实际结果。AI 可以引用步骤、截图或规则提出原因及建议，由开发者标记采纳/不适用；AI 不自动改源文件。第三方网站不属于团队可随意修复的代码资产。

## 7. AI 只给可核对的建议

第 16—17 周将用户口语目标与**经过筛选的当前页摘要**发送给模型，要求返回目标、候选编号、理由、待追问信息和页面版本。程序先检查输出结构，再核对编号仍在当前网页、控件真实存在，用户选择后才走下一步；模型不能给出任意 URL、选择器、脚本或提交命令。在未设专属任务卡的第二个公开网站，先验证阅读和找入口。模型失败时回到本地查找及人工选择。

```ts
type ModelSuggestion = {
  goal: string;
  pageVersion: number;
  candidateIds: string[];
  reason: string;
  clarification?: string;
};
```

不默认上传密码、填入值、个人信息、整页正文或评测截图。开发端的 AI 修复建议也必须绑定真实证据，留人工处理记录。

## 8. 数据、接口和可复现性

| 数据 | 关键字段与限制 |
|---|---|
| `tasks` | 目标、网站类型、起点、步骤、完成判据、审核版本 |
| `runs`、`run_steps` | 来源（用户/评测）、网址、页面版本、状态、耗时、每步结果 |
| `issues`、`retests` | 原失败、证据路径、修复前后运行编号、人工核对 |
| `study_results` | 匿名编号、任务/网站版本、受试者分组、结果、耗时、步骤、求助与评分 |

接口按周实现：`GET/POST /tasks`、`POST /runs/evaluations`、`GET /runs/:id`、`GET /runs/:id/issues`、`POST /issues/:id/retests`、`GET/POST /study-results`、`POST /assistant/suggestions`、`POST /assistant/runs/:id/confirm`。评测目标由任务和测试配置审核；桌面主进程对用户当前视图的操作不开放为远程任意浏览器控制接口。用户输入网址可以导航，但不意味着获准自动提交。运行记录必须标明来源、站点版本、任务版本和失败原因。

## 9. 与逐周任务对应

细分页面、两人的每周步骤和交接验收以最新版周卡为准；每周交付修改文件、启动命令、成功与失败各一例，由队友复现。

| 时间 | 新增技术能力 | 应展示的成果 |
|---|---|---|
| 启动周及第 1 周（11 月） | Electron 窗口、网址栏、独立网页视图、右侧助手、两系统开发启动 | 两个网站的导航、标题、返回/前进/刷新及失败提示 |
| 第 2—3 周（11 月末—12 月初） | 页面提取、概要、跨站候选入口与高亮 | 真实控件列表和失效编号检查 |
| 第 4—6 周（12 月） | 通用动作、任务编辑、隔离评测、时间线与两站对照 | 两站只读记录；失败截图不影响用户窗口 |
| 第 7—11 周（12 月末—1 月） | 页面变化重验、规则检查、问题单、修复复测和人工走查 | 日期标签问题的发现—修复—复测闭环 |
| 第 12—15 周（2 月） | 步骤卡、资料卡、本人确认、暂停恢复、历史和无 AI 回退 | 自建站表单流程与重复提交防护 |
| 第 16—17 周（3 月上旬） | AI 入口/步骤候选、用户核对、模型失败回退、证据建议 | 未写专属卡的公开站只读任务 |
| 第 18—20 周（3 月中下旬—4 月初） | 固定测试条件、试用、失败修复、候选版冻结 | 四个案例、分组记录及能力边界 |
| 第 21—24 周（4 月） | Mac/Windows 实际试装、帮助、归档、彩排 | 两套安装包及可由队友独立复现的案例 |

苏越负责外站视图、导航、提取、动作层、评测、AI 接入和整体联调；巩品言负责网址栏、右侧助手、工作台及测试站的可见页面，参与记录、问题单、试用数据接口和测试。涉及接口，先交地址、输入、正常与错误结果；演示数据界面标注“演示”，接通真实网页后再验收。

## 10. 试用、打包与交付

第 18 周固定两个公开站只读任务和自建站表单任务。争取 10—15 人试用，记录**实际人数**，学生与目标用户分别统计；对照直接操作与助手操作时保持条件可比，记录成功、耗时、步骤、求助、清晰度和原话。每个数字可追溯到原始记录。第 20 周后主要修复问题，不再追加大功能。

第 21 周在 Mac 和 Windows **各自从安装包试装**，检查网址、导航、页面提取、无 AI 回退和权限提示；不能只在开发机上以开发服务运行。第 22—24 周归档锁定依赖、源码、两个安装包、部署/使用说明、证据和不能适配的网站与登录清单。遇到新窗口、验证码、下载或结果不明，给出暂停和人工处理办法。
